# Frontend

`packages/web` is a Vite + React 19 single-page app. It talks to the API only through `/api/*` on the same origin: the Vite dev server proxies to the API on `API_PORT` (default 8080), and in production Nest serves the built app. There is no CORS and no API base URL. See the tooling skill for commands.

## Design reference

This skill is the design reference. The design is final: colours, type, spacing, radii and interactions are settled. Match the existing components and the values here; do not invent new ones. Where a value lives in code, the table names the file instead of repeating it. The later sections ("Styling", "UI components", "Media components" and the screen sections) describe how each piece is built.

## Routing

- File-based routing via `@tanstack/router-plugin`. Adding a file under `src/routes` adds a route; the plugin regenerates `routeTree.gen.ts` while `pnpm dev` or `pnpm build` runs.
- Export `Route = createFileRoute('/path')({ component })` from each route file. Keep the page component in the same file unless it is reused.

### Tabs: the `navigation.ts` contract

`src/navigation.ts` is the single source for tabbed sections. The shell, the tab pills and the screens import from it; never repeat a tab id or label as a string literal elsewhere.

- `MUSIC_TABS`, `VIDEO_TABS`, `SETTINGS_TABS`: readonly tuples of the lowercase URL ids, in display order.
- `MusicTab`, `VideoTab`, `SettingsTab`: their union types.
- `DEFAULT_MUSIC_TAB` (`albums`), `DEFAULT_VIDEO_TAB` (`videos`), `DEFAULT_SETTINGS_TAB` (`general`).
- `TAB_LABELS`: display label per tab id (`albums` → `Albums`). The ids are unique across sections.
- `TAB_ICONS`: icon component per tab id for the tab pills (see Icon registry).
- `parseTab(tabs, value)`: the tab, or `undefined` when `value` is not one of `tabs` (exact, lowercase).

### Typed params and redirects

- A `$tab` route declares `params: { parse, stringify }`. `parse` returns `{ tab: MusicTab }` (annotate the return type), so `Route.useParams()` and `Link`'s `params` are typed with the union.
- An unknown tab never renders: `parse` throws `redirect({ to, params: { tab: DEFAULT_… }, replace: true })`. The router runs `parse` while matching, before `beforeLoad`, and treats a thrown redirect as a redirect, so this is the one place the check lives.
- A bare section (`/music`) has a `*.index.tsx` route with only `beforeLoad: () => { throw redirect({ …, replace: true }) }`.
- Always `replace: true` on these redirects so browser back skips the URL that redirected.
- Link to a tab with `<Link to="/music/$tab" params={{ tab: 'tracks' }}>`; link to a section with its default tab rather than the bare path, which saves a redirect.

### Search params

State that should survive a reload or a shared link lives in the URL search params, validated by the route's `validateSearch`. `/music/$tab` has the Tracks tab's `q`, `filter`, `sort` and `dir` (`TrackSearch`): `parseTrackSearch` (in `components/library/track-list.ts`, tested) keeps valid values and drops invalid ones and defaults, so the plain `/music/tracks` is All sorted by Added descending and a hand-edited URL never breaks the page. Every field is optional, so links to the other tabs need no `search` (and drop it). Screens read with `useSearch({ from: '/music/$tab' })` and write with `useNavigate({ from: '/music/$tab' })` and `resetScroll: false`; typing replaces the history entry, a filter or sort click pushes one (browser back undoes it).

### Adding a tabbed section

1. Add `FOO_TABS`, `FooTab`, `DEFAULT_FOO_TAB` and the labels to `navigation.ts`, and cover them in `navigation.spec.ts`.
2. Add `foo.$tab.tsx` with the `params` block above and `foo.index.tsx` with the redirect.
3. Run `pnpm dev` or `pnpm build` so the plugin regenerates `routeTree.gen.ts`, and commit it.

## Data fetching

- React Query for all server state. `queryKey` arrays name the resource, for example `['health']`, `['channels', id]`.
- Plain-text endpoints (job logs) go through `apiGetText(path)`.
- Call the API through `apiGet(path, Schema)`, `apiPost(path, body, Schema)`, `apiPatch(path, body, Schema)` and `apiDelete(path)` from `src/api/client.ts`. They validate the JSON against the shared Zod schema and throw `ApiError` (`status`, raw `body`, `json()`) on non-2xx.
- Show a failed request with `apiErrorMessage(error, fallback)`: the API's `message` as a sentence, with validation `issues` and a yt-dlp `reason` appended; `fallback` for network errors and non-JSON bodies.
- A screen whose query failed shows `ErrorState` (see "Empty and error states"); `loadErrorDetail(error)` in `client.ts` is its second sentence: the API's message, `The server answered 502.`, `The server did not answer.` (fetch rejected) or `The answer was not in the expected shape.` (Zod).
- Never hand-write response types in the web package. Import schemas and types from `@mytube/shared`.

### Theme

- `data-theme="light" | "dark"` on `<html>` forces a theme. Without it, `prefers-color-scheme` decides. The dark values live in `styles.css` twice (attribute and media query); keep them identical. `red`, `ok` and `white` are the same in both themes.
- Components never branch on the theme and never use the `dark:` variant; the tokens swap underneath them.
- `useTheme()` from `src/theme.ts` returns `{ theme, resolvedTheme, setTheme }`. `theme` is the choice (`'light' | 'dark' | 'system'`), `resolvedTheme` what is on screen (`'light' | 'dark'`), `setTheme(choice)` sets the attribute and caches the choice in localStorage under `mytube.theme` (`system` clears it). An inline script in `index.html` applies the cached choice before first paint.
- **The source of truth is the settings table** (`general.theme`, see the architecture skill). The root layout calls `useThemeFromSettings()`, which applies the stored theme with `setTheme` once settings load. Screens change the theme with `useUpdateSettings().mutate({ general: { theme } })`, which calls `setTheme` optimistically and reverts it if the save fails. A bare `setTheme` (as on `/dev/tokens`) only lasts until the next settings load.
- Settings → General offers Light, Dark and **System**, so the user can go back to following the device.

### Focus and motion

Defined once in `styles.css`; components never write their own `transition` or outline values.

- **Focus:** a global `:focus-visible` rule gives every focusable element the ring (2px red outline, offset 2px) without opting in. Utilities for the variants: `focus-ring` (the same ring, explicit and immune to `outline-none`), `focus-ring-inset` (offset -2px, for items inside a clipping container: tab pills, nav rows, the channel link in a tile chin) and `focus-ring-overlay` (rings the element when its descendant marked `data-overlay` has keyboard focus; for overlay-button tiles). `cx.ts` exports them as `focusRing`, `focusRingInset` and `focusRingOverlay`; interactive components list one of them.
- **Motion** (nothing else animates): `motion-tile` (tile hover: scale, shadow and background, .2s ease), `motion-chin` (chin reveal: translate, .2s ease), `motion-knob` (toggle knob: `left` .15s). Put the utility on the element whose property changes; the hover or state classes stay on the component. All three drop the animation under `prefers-reduced-motion: reduce`. Buttons, pills and bells do not animate.
- `/dev/tokens` shows the motion utilities and the focus ring.

## UI components

`src/components/ui/` holds the core design system components, one file per component, named exports. Screens and layouts use these instead of raw utilities: no hand-built buttons, pills, inputs or type classes on pages. `/dev/components` shows every one of them and their variants. Import each from its own file (`../components/ui/Button`); there is no barrel.

- `typography.tsx`: `PageTitle` (h1), `ModalTitle` (h2), `SectionTitle` (h2), `SectionLabel` (h2, muted), `TableHeaderLabel` (span, muted), `Meta` (span; `size="md" | "sm"`, `tone="muted" | "ink" | "ok" | "red"`), `Body` (p; `muted`), `FieldLabel` (label; `htmlFor`). All take `as`, `id`, `className`.
- `PageHeader`: `title`, `sub?`, `actions?` (a `StatCardGroup` or `TabPills`). Bottom-aligned, wraps on narrow. **The sub line's height is always reserved** (an empty `aria-hidden` line of `1lh` when there is no `sub`), so every header is equally tall and the tab pills sit at the same y on every section; do not render a header without it. Settings passes no `sub` (by design: "Settings" and the pills only); do not add filler subtitles.
- `StatCard`: `label`, `value`. `StatCardGroup` lays out several with gap 10.
- `TabPills<T>`: `items: {id, label, icon?}[]`, `value`, `onChange(id)`, `label` (group aria-label), `size="md" | "sm"`. Controlled toggle buttons with `aria-pressed`. `icon` is an icon component from `components/icons`, drawn at 16px, 8px before the label, on wide screens only (hidden below 760px). The track scrolls inside itself instead of widening the page and scrolls the active pill into view. The scroll runs one task after render, because TanStack's scroll restoration otherwise copies the old `scrollLeft` back after navigation.
- `TabPillLinks<T>` (same file): the routed variant for tabs that live in the URL. `items: {id, label, icon?, link}[]` where `link` comes from `linkOptions({ to, params })`, `value` (the current tab from `Route.useParams()`), `label` (nav aria-label), `size`. Renders a `<nav>` of `Link`s with the identical track and item classes (shared `trackClass`/`itemClass` helpers, never copy them), `aria-current="page"` on the active pill. Build the items once at module level from `navigation.ts`: `MUSIC_TABS.map((tab) => ({ id: tab, label: TAB_LABELS[tab], icon: TAB_ICONS[tab], link: linkOptions({ to: '/music/$tab', params: { tab } }) }))`, and pass the track as `PageHeader`'s `actions`.

- `Button`: `variant="primary" | "secondary" | "outlined"` (default secondary), `size="md" | "lg" | "xl"`, `icon?` (leading), `fullWidth?`, plus native button props. `md` Archivo 13 at 9px 16px ("Edit rules"), `lg` Archivo 14 at 11px 18px (modal footer; primary is 700 with 20px sides), `xl` Archivo 700 15 at 13px (the sidebar "Add to library", used with `fullWidth`). Padding includes the 1px border every variant has.
- `IconButton`: `label` (required, becomes `aria-label`), `size="sm" | "md" | "lg"` (32/36/40px), `tone="surface" | "red"`, icon as the child.
- `Input`: `shape="field" | "pill" | "value"` (default field, radius 10; `value` is the Settings value box, see Settings components), `mono` for URLs and paths, `width?` (defaults to full width), `chars?` (native `size`; a `value` box is as wide as that many characters on wide screens), plus native input props.
- `Toggle`: `checked`, `onChange(checked)`, `label?` (aria-label when there is no visible label). `ToggleRow`: `label`, `description?`, `checked`, `onChange`, `disabled?`; the whole row is clickable.
- `CheckboxRow`: `label`, `hint?`, `checked`, `onChange(checked)`, `disabled?`. A native checkbox underneath. Label and hint share a wrapping line, so on a narrow screen a long hint moves under the label instead of squeezing it.
- `Modal`: `open`, `onClose`, `title?`, `aria-label?`, `dim="default" | "strong"`, `width?` (CSS, default `min(560px, 100%)`), `maxHeight?` (CSS; Preview passes `calc(100vh - 48px)`), children as the body. Two variants:
  - **With `title`** (Add to library, confirmations): padding 28, gap 22, a title row with the round close button; the title names the dialog.
  - **Header-less** (Preview): omit `title` and pass `aria-label` (the types require one or the other). No title row, no close button, no padding, `overflow: hidden`; the children lay out the whole dialog (player area, footer).
  - `dim="default"` uses `bg-scrim` and the modal shadow; `strong` uses `bg-scrim-strong` and the preview shadow.
  - Portals to `body`; closes on overlay click and Escape; locks body scroll; focuses the dialog on open, keeps Tab and Shift+Tab inside it, and restores focus on close. Open modals form a module-level stack: only the top-most reacts to Escape and Tab, so a confirm opened from Preview closes first. `ModalActions` is the right-aligned footer row.
- `focus.ts`: `trapTab(event, container)` (the Tab/Shift+Tab trap), `tabbableWithin(container)` and `createLayerStack()` (the modal stack). Use them for any future overlay (menus, popovers) instead of a dependency.
- `EmptyState` (children, `action?`): what a screen shows with nothing to list, one plain muted `Body` line in a `role="status"` block, the optional action under it. See "Empty and error states".
- `ErrorState` (`what`, `error`, `onRetry?`, `retrying?`, `verb?`): `Could not load <what>. <loadErrorDetail(error)>` in muted `Body` (`errorStateText`), then an outlined **Retry** (`Retrying…` and disabled while `retrying`), in a `role="alert"` block that wraps on narrow. `fromQuery(query)` gives `error` (`error`, else the `failureReason` of an attempt still being retried), `onRetry` (refetch) and `retrying` (`isFetching`) from a React Query result: `<ErrorState what="the videos" {...fromQuery(videos)} />`. `loadFailed(query)` decides when to show it: no data and a failed attempt (`failureCount > 0` or `isError`), so the error appears on the first failure with "Retrying…" instead of after the whole retry backoff. `verb="show"` is for render errors.
- `cx.ts`: `cx(...classes)` joins class names (no clsx), plus the shared class strings `focusRing`, `focusRingInset`, `focusRingOverlay` (names of the focus utilities in `styles.css`, see "Focus and motion"), `minHit` (min height 44px narrow, 36px wide) and `hitArea` (invisible 44px/36px pseudo-element hit area for visually smaller controls like the 32px close button and the switch). Every interactive component uses them; new ones must too.

Tailwind 4 note: `outline-none` sets `--tw-outline-style: none`, which also hides a later `outline-2`. Use the focus utilities instead of building a ring from `outline-*` classes.

No spin buttons (the value box has none by design); arrow keys step.
- `Input shape="value"`: the value box as a text input. For settings use `TextValueInput`, which wraps it.
- `TextValueInput` (`value`, `onCommit(text)`, `validate?(text) => message | undefined`, `placeholder?`, `id?`, `label?`, `disabled?`, `secret?`): free text in the value box (templates, paths, rate limits, language lists). Saves on **blur or Enter**, not per keystroke (partial text is rarely valid); Escape reverts. Invalid text stays in the box, red with the message under it (`aria-describedby`), until fixed or reverted. The draft stays on screen until the saved value arrives, so the box does not flash back. Grows with its text on wide screens (20 to 56 characters, `valueInputChars`), full width on narrow. Validate with the shared schema (`schemaError` in `components/settings/fields.ts`), so the message matches the API's 400. `secret` masks the text (`type=password`, `autocomplete=new-password` so password managers stay out) for tokens.
- **Several controls in one value cell** (Subtitles: list + delivery select): the row's `<label>` goes to exactly one control through `useFieldId`; give every other control its own `id` (`useId()`) and a `label` (aria-label), or two controls end up with the same id.

- `valueBox` in `cx.ts`: the value box classes (`surface`, Space Mono 13, 9px 12px, radius 8, `max-content` with min 160px wide, full width narrow). Use it for any new value control.

### Rule builder: `components/rules/`

The rules of a source are one matcher tree (architecture skill, settled decisions; backend skill "Matchers"). There is no checkbox mode.

- `matcher-draft.ts` (pure, `matcher-draft.spec.ts`): the editing state. `DraftGroup` `{ kind: 'group', id, gate: 'and' | 'or', negated, items }` and `DraftLeaf` `{ kind: 'leaf', id, type, negated, text, pattern, date, days, seconds, status, channel, position }` (every leaf keeps every parameter, so switching a condition's type and back loses nothing). There is no NOT gate (decided by Thomas: NOT over several children reads badly and the toggles express it, since NOT(A OR B) = AND(NOT A, NOT B)); every node, group or condition, has a NOT toggle (`negated`) that wraps it in the schema's `not`. Loading a tree folds each `not` into the toggle of the node it wraps, so a `not` around a group shows as the group's toggle, one around a condition as the condition's, and double negations cancel. `draftFromMatcher(matcher)` (the root is always a group) and `matcherFromDraft(root, { playlist })` → `{ ok, matcher }` or `{ ok: false, error }` (the first problem: empty text, invalid regex via shared `regexError`, missing date, out-of-range numbers, an empty nested group, an empty root other than AND, a playlist-only condition outside playlists, then the shared schema's depth and size limits). `nodeError(node, { root, playlist })` for inline messages. Edits return a new root and keep untouched nodes' identity: `addNode`, `removeNode` (never the root), `moveNode` (±1 within its group; no UI yet), `updateLeaf`, `setGate`, `canAddGroup` (stops offering "Group" before the depth limit). `setNegated` flips any node's toggle. `newLeaf()` is an empty "Title contains", `newGroup()` an OR with one empty condition. `LEAF_OPTIONS` / `leafOptions(playlist)`, `LIVE_STATUS_OPTIONS`, `GATE_LABELS` (`AND`, `OR`) and `groupHint(gate, negated)`: all of / any of these, and with NOT not all of / none of these. The root may be negated too; an empty root is only valid as a plain AND.
- `MatcherBuilder` (`value`, `onChange`, `playlist`, `label?` default "Rules"): a labelled group. Each group: its NOT toggle, a small `TabPills` (AND / OR) with its hint in Space Mono (`groupHint`), a × (`IconButton` sm, `CloseIcon`) on nested groups, then its items indented behind a 2px `line` left border, and outlined **Condition** (`AddConditionIcon`) and **Group** (`AddGroupIcon`) buttons. A condition row is a grid: a NOT toggle (a small Space Mono pill with `aria-pressed`, red when on), the type `Select` with its value control (text `Input shape="value"` for title / regex / channel, a date input, `NumberInput` with a `days` / `seconds` unit, a live status `Select`; nothing for "Is a short" and "Is members-only"), which wraps under the type when the row is too narrow, and a × pinned to the top right. ## App shell

`src/components/shell/AppShell.tsx` is the layout, rendered by `routes/__root.tsx` around `<Outlet />`. `/dev/*` pages are left outside it and render their own `<main>`.

- **Wide (`wide:`, 760px and up):** `Sidebar` (232px, sticky, full height, `side` bg, `line` right border) with the lockup, the five `NavItem`s, a spacer, the "+ Add to library" button and a footer slot. Main is fluid with `min-width: 0`.
- **Add buttons:** the top bar "+" is `ui/IconButton` (`tone="red"`, `size="lg"`). The sidebar pill is `ui/Button` (`variant="primary"`, `size="xl"`, `fullWidth`, `PlusIcon`).
- **Narrow:** the sidebar is hidden, `TopBar` (sticky, lockup + round red "+") sits at the top of main, `TabBar` (five sections, fixed to the bottom, safe-area aware) sits below everything.
- **Main owns the outer padding and section rhythm:** padding 32px 40px 64px wide and 0 16px 96px narrow (the 96px clears the tab bar), and a flex column gap of 28px wide / 20px narrow between page sections. Pages set **no** outer padding, margin or max width on their root; they render their sections (header, tab pills, grid, ...) as direct children, usually through a fragment. Content max widths such as the Settings column (760px) belong on the section itself.
- **Props from data:** `activityCount` (active downloads; the Activity badge shows when above 0, in both the sidebar and the tab bar) and `sidebarFooter` (a node, normally `<SidebarFooter version status />`, which renders `yt-dlp <version>` over the status line). The root passes `useActivitySummary().data?.activeDownloads` (download jobs queued or running), and `<YtdlpFooter />` (`components/shell/YtdlpFooter.tsx`), which feeds `SidebarFooter` from `useYtdlpStatus()`: `yt-dlp <installedVersion or —>` over `<state label> · auto-update <on|off>` (`loading…` / `status unavailable` before data). `SidebarFooter` splits the status line at `·` and keeps each part on one line, so a long status wraps at the separator.

### Nav sections and the active state

- `navigation.ts` holds `NAV_SECTIONS` (`home`, `music`, `video`, `activity`, `settings`, in display order), `NAV_SECTION_LABELS` and `sectionOfPath(pathname)`.
- Active state is **section-level**: `sectionOfPath` maps a pathname to its section by the first path segment, so `/music/tracks` keeps Music active and `/video/channel/abc` keeps Video active; Home matches `/` only. The shell reads it through `useActiveSection()` in `components/shell/sections.tsx` and sets `aria-current="page"` on the active link. Do not use `Link`'s `activeProps` for the nav: the section links point at the default tab (`/music/albums`), which would not match the other tabs.
- Section links go to the default tab (`SECTION_LINKS` in `sections.tsx`), never to the bare section path.

### Global UI state: `ui-state.ts`

A tiny external store (the `useSyncExternalStore` pattern from `theme.ts`) for dialogs that any screen can open. `useAddModal()` returns `{ open, openAdd, closeAdd }`. Every Add button (sidebar, top bar, and later the empty states) calls `openAdd`; `AppShell` mounts `AddSourceModal` only while `open` is true (so each opening starts empty) and passes `closeAdd` as its `onClose`. `usePreview()` returns `{ target, openPreview, openTrackPreview, openEmptyPreview, closePreview }`: video tiles call `openPreview(id)`, music tiles `openTrackPreview(id)` or `openEmptyPreview(title)`; `AppShell` mounts `PreviewModal` (keyed by `previewKey(target)`, so each opening starts at the poster) while `target` is set. Add more global dialogs here rather than threading state through props.

## Empty and error states

By design they are plain muted Archivo 14 text. Every screen uses the two named components from `components/ui/` (never a hand-written `<Body muted>` for these):

- **Empty:** `EmptyState` with one or two dry sentences. Copy in use: Home "Nothing downloaded yet. Add a channel or an artist to get started." (with the Add to library button, the only one) or "Nothing downloaded in the last 14 days."; Videos and the channel page "Nothing downloaded yet."; Channels "No channels yet. Add one with + Add to library."; Artists, Albums, Playlists "No … yet. Add … with + Add to library."; Tracks "No tracks yet. …" and "No tracks match."; Activity "Queue is empty." and "No history yet."; channel page 404 "This channel is not in your library.".
- **Failed request:** `ErrorState what="<the thing>" {...fromQuery(query)}` when `loadFailed(query)`, that is only while the query has no data (a failed background refetch or poll keeps what is on screen). Retry refetches. Settings uses it in `SettingsTab` ("Could not load the settings.").
- **Render error:** `defaultErrorComponent: RouteError` in `main.tsx`. A route that throws renders `Could not show this page. <message>` with Retry (resets the boundary and invalidates the router) inside the app shell.
- Loading lines stay `StatusLine` ("Loading tracks."); there are no spinners and no toasts.
- `/dev/components` shows both components; `states.spec.tsx` renders them with `react-dom/server`.

## Component structure

- **Pages and semantic components compose named components.** A page should read like the design: `<PageHeader>`, `<TabPills>`, `<TileGrid>`, `<StatCard>`. Long Tailwind class lists do not belong on pages, layouts or other high-level components.
- **Class lists live inside the leaf components** that implement the design system (`src/components/**`), and those use the token utilities (`bg-surface`, `text-muted`, `rounded-tile`, `text-section-label`) rather than raw values.
- **Type roles are components too.** Wrap the type utilities in small components such as `<PageTitle>`, `<SectionLabel>` and `<Meta>` so screens never repeat `text-h1` or `text-meta`.
- A component takes semantic props (`variant="primary"`, `subscribed`, `incomplete`), not class names, except an optional `className` for layout placement by the parent.

## Conventions

- Function components, hooks, no class components.
- Imports use no file extensions (bundler resolution).
- Component library conventions: see "UI components" above.
